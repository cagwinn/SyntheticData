## Lessons + meta-observations

1. **Memory architecture is multi-layered.** C1 Phase 1 solved 200 GB
   of TB hold but left 200-400 GB of JE hold; Phase 2 solved that but
   left 100+ GB of IC matcher clones. Each layer of the aggregate has
   its own peak. Phase 3 + future "stream everything" work will need
   the same per-layer analysis.

2. **Methodology debt compounds.** T3 revealed that v5.30's headline
   numbers (134 → 121 composite, P1 autocorr 105.9 → 62.8) were
   single-shard point estimates with 25 % CV across seeds. Every
   v5.30 dataset card on HF cites the high-side draw. Future engine
   claims need multi-seed evidence before being treated as deltas.

3. **Streaming refactors propagate naturally.** The Phase 1 → Phase 2
   pattern (move data to streaming writers + filter for downstream
   consumer's needs) generalises: applies to IC matching, FS assembly,
   notes, NCI rollforward. Each downstream layer that holds
   `Vec<X>` is a candidate.

4. **Group-audit configuration has multi-level inheritance gaps.**
   The `fraud:` block missing from `GroupConfig.defaults` echoes the
   #148 row-budget propagation failure. The `defaults → scoping_profile
   → entity` cascade flattening in `manifest/builder.rs` doesn't cover
   all generator-config fields. A systematic audit of which config
   fields *do* flow through vs which silently default is overdue.
