# DataSynth v4.1.0 Plan — 2026-04-21

## Context

v4.0.1 closes out a 14-release sprint (v3.3.2 → v4.0.1) that cleared
the entire `unused-features-inventory.md` backlog plus the major
v4.0 cleanup items. The runtime now honors every previously-inert
`distributions` sub-block and the LLM enrichment CLI is live against
OpenRouter.

Three classes of follow-up work remain:

1. **Partial completions** — features where the infrastructure is in
   place but only part of the full behavior ships. Low-risk
   increments, each a self-contained release.
2. **Schema knobs validated-but-inert** — 3 sections confirmed inert
   (`behavioral_drift`, `market_drift`, `drift_labeling`) and 3 more
   partial (`vendor_network`, `customer_segmentation`,
   `industry_specific`). Either wire them or document + deprecate.
3. **Major items** — YAML-as-SoT migration, neural diffusion, graph-
   export consolidation. Each is a separate multi-week effort; plan
   each as its own release rather than bundling.

Per user direction, plan all under a v4.1.x umbrella (not v4.x
spread). The major items each get a dedicated patch release within
v4.1.x so they can ship independently when ready.

## Goals

- Close every "validated-but-inert" schema knob, either by wiring it
  to runtime behavior or by explicit deprecation with a migration
  path.
- Complete the distribution track started in v3.4-v3.5: all copulas
  live, full field-to-field conditionals, full validation suite.
- Broaden the LLM enrichment surface: finding titles/narratives,
  multi-category runtime enrichment, per-industry prompt library.
- Unlock the audit-optimizer crate (crate exists, only 1 of 7
  subcommands surfaced).
- Ship YAML-as-source-of-truth for name pools, preserving
  byte-identity under the same seed.
- Preserve every v4.0 invariant: seed-in → byte-identical-out on
  default configs; ~200 K entries/sec single-threaded corridor.

## Release sequence

```
v4.0.1 (shipped)
  │
  ├──► v4.1.0   — distributions completion (copulas + conditionals + validation)
  │      │
  │      ├──► v4.1.1   — LLM track completion (findings + prompts + orchestrator broadening + CI matrix)
  │      │
  │      ├──► v4.1.2   — audit-optimizer CLI (6 subcommands) + 3 inert-schema decisions
  │      │
  │      ├──► v4.1.3   — partial-schema follow-through (vendor_network, customer_segmentation, industry_specific)
  │      │
  │      ├──► v4.1.4   — YAML-as-SoT migration (byte-identity gated)
  │      │
  │      └──► v4.1.5   — graph-export consolidation
  │
  └──► v4.2.0   — neural diffusion (only if contributor surfaces; otherwise stays deferred)
```

v4.1.0 through v4.1.3 are sequential but any of them can ship as
patch releases in parallel sub-branches since their surfaces don't
overlap. v4.1.4 (YAML-as-SoT) and v4.1.5 (graph-export) are
substantial enough to each warrant their own release.

Calendar estimate: **6–8 weeks** for the full v4.1.x line, gated on
how fast regression passes clear. v4.2 only fires if a neural
contributor shows up.

## v4.1.0 — Distribution completion

**Effort: L (6–8 days).** Closes the distribution-sampling track.

### Scope

Six items from the v3.5 deferred list:

1. **Inverse-CDF amount↔line_count copula.** Bidirectional
   correlation. `v` from the copula drives line_count via quantile
   inversion of `LineItemSampler`'s configured distribution. This is
   the real bivariate coupling v3.5.4 teased.
2. **Clayton / Gumbel / Frank / Student-t copulas runtime.**
   `set_advanced_distributions` removes the Gaussian-only filter.
   Each copula gets a smoke test proving its empirical Kendall-τ
   matches theory within ±0.05.
3. **Full field-to-field conditional dependency.** Drop the
   `input_field ∈ {month, quarter, constant}` restriction. New
   `ConditionalEngine` holds a DAG of field-to-field dependencies
   (e.g. `line_count` depends on `amount` which depends on `month`),
   topo-sorts at construction, and resolves values in order per JE.
4. **More conditional inputs.** `company_index`, `year`,
   `day_of_week`, `day_of_month`, `business_process`,
   `is_period_end` — all trivially computable per-JE.
5. **`CorrelationCheck` and `AndersonDarling` validation tests.**
   Complete the v3.5.1 statistical-validation phase. Currently
   `Skipped` with a message; replace with real implementations.
6. **`ExpectedCorrelationConfig` validation.** When declared in
   `distributions.correlations.expected_correlations`, the
   validation phase asserts empirical Spearman correlation is within
   the configured tolerance.

### Critical files

- `crates/datasynth-generators/src/je_generator.rs:200-400` —
  `set_advanced_distributions` + `correlation_copula` field. Removal
  of the `matches!(Gaussian)` gate; addition of v-quantile-inversion
  for line_count.
- `crates/datasynth-core/src/distributions/copula.rs` — copula-type
  match in `BivariateCopulaSampler` (already present; verify
  implementations are numerically sound for all 5 types).
- `crates/datasynth-core/src/distributions/conditional.rs` — new
  `ConditionalEngine` wrapping a dependency DAG.
- `crates/datasynth-core/src/distributions/validation.rs` — add
  `run_correlation_check`, `run_anderson_darling`,
  `run_expected_correlations`.
- `crates/datasynth-runtime/src/enhanced_orchestrator.rs` —
  `phase_statistical_validation` dispatches new test types.
- `crates/datasynth-config/src/schema.rs` —
  `ConditionalDistributionSchemaConfig` + `CorrelationSchemaConfig`
  enrichment. No breaking changes; everything additive.

### Testing

- `crates/datasynth-core/src/distributions/copula.rs#tests` — new
  unit test per copula type asserting empirical Kendall-τ vs. theory.
- New integration test `conditional_dag_smoke.rs` — declare a
  3-field DAG (month → amount → line_count), generate 10K JEs,
  verify (a) the DAG resolves without cycles, (b) Spearman
  correlation of amount vs line_count is > 0.3.
- Extend `correlations_smoke.rs` with Clayton / Gumbel / Frank /
  Student-t empirical-τ assertions (within ±0.05).
- Extend `statistical_validation_smoke.rs` with real
  AndersonDarling (log-normal target) and CorrelationCheck cases.

### Evaluation

- Grep for `TestOutcome::Skipped` in
  `phase_statistical_validation` — count should drop to 0 except for
  small-sample guards.
- `cargo clippy --workspace --all-targets -- -D warnings` clean.
- Byte-identity regression: `distributions.correlations.enabled =
  false` with default copula config must still produce the v4.0.1
  output.

### Rollback

- Per-feature flags: `correlations.enabled`, `conditional.enabled`
  already in schema. Setting each to false restores pre-v4.1.0
  behavior.

### Risks

- Empirical Kendall-τ for Frank at small |θ| can drift outside ±0.05
  over 10K samples. Budget time to raise the sample count or widen
  the tolerance for extreme θ.
- The DAG-based `ConditionalEngine` introduces topo-sort overhead
  per-construction; perf-bench the JE pipeline.

   `FindingLlmEnricher` parallel to `VendorLlmEnricher`. Schema:

- `crates/datasynth-runtime/src/enhanced_orchestrator.rs:4652-4800`

### Testing

- Integration `phase_llm_enrichment_smoke.rs` — run full pipeline

## v4.1.4 — YAML-as-source-of-truth migration

**Effort: L (1–2 weeks).** The v4.0.0 foundation is `TemplateLoader::
load_from_yaml_str`. Complete it:

### Scope

1. **Export all embedded arrays to YAML.** Every `const *_NAMES /
   DESCRIPTIONS: &[&str]` in `datasynth-core/src/templates/*.rs` and
   `datasynth-generators/src/master_data/*.rs` → a single canonical
   `crates/datasynth-core/templates/defaults.yaml` committed in
   repo.
2. **`build.rs` validation.** Parses `defaults.yaml` at build time,
   asserts it round-trips against a snapshot of the embedded
   arrays. Fails the build if the YAML drifts.
3. **Rewrite `DefaultTemplateProvider::new()`.** Use
   `include_str!("../../templates/defaults.yaml")` + `load_from_
   yaml_str` to construct. Keep the `const` arrays as the
   build-time snapshot source so byte-identity is provable.
4. **Regression test.** `yaml_migration_smoke.rs` — generates with
   old and new provider, asserts byte-identity for a canonical seed.

### Critical files

- `crates/datasynth-core/templates/defaults.yaml` — new, ~thousands
  of entries.
- `crates/datasynth-core/build.rs` — new.
- `crates/datasynth-core/src/templates/provider.rs:
  DefaultTemplateProvider::new` — rewrite.
- All `const *_NAMES` consumers: transitive sweep to confirm they
  still resolve through the provider.

### Testing

- `yaml_migration_smoke.rs` — seed 42, generate 10K JEs, compare
  pre-migration checksum (captured by `cargo run --bin datasynth-
  data generate --seed 42 --output snapshot-pre.tgz` on v4.1.3) to
  the v4.1.4 output. Hash must match.
- `build.rs` unit: delete a line in `defaults.yaml`, confirm build
  fails.

### Evaluation

- Pre-migration hash (captured on v4.1.3) vs post-migration hash
  match byte-for-byte on seed 42.
- `crates/datasynth-core/templates/` committed; embedded arrays
  deleted from `.rs` files.

### Risks

- The export is tedious: easy to miss a pool. Mitigation: script
  the export from a running provider via `templates export --all`.
- Non-byte-identity risks: any ordering-sensitive YAML deserialization
  (e.g. HashMap iteration). Use `IndexMap` or sort-on-deserialize to
  lock order.

### Rollback

- Keep the embedded arrays in the codebase behind
  `#[cfg(feature = "embedded-defaults")]` for one release (v4.1.5
  removes them). This way if the YAML migration has a bug, users can
  build with `--features embedded-defaults` to restore.

## v4.1.5 — Graph-export consolidation

**Effort: M–L (5–7 days).**

### Scope

Two graph-export surfaces coexist today:

- `datasynth-graph` (in-workspace) — embedded snapshot on
  `EnhancedGenerationResult`; PyTorch Geometric, Neo4j, DGL writers.
- `datasynth-graph-export` (excluded from default workspace) —
  standalone pipeline with its own writers.

Decision: **consolidate into `datasynth-graph`.** The embedded path
is the one all production callers actually use, and
`datasynth-graph-export` has been excluded (not built) for months.
Migration:

1. **Port unique features** from `datasynth-graph-export` into
   `datasynth-graph`. Candidates per `STATUS.md`: cleaner writers
   for the ML-training case, optional GraphML / GEXF support.
2. **Move the excluded crate to `attic/`.** Deleted from
   `Cargo.toml` exclude list; moved into a dedicated attic
   directory that isn't part of the build.
3. **Update `CLAUDE.md`** to remove the 16-active-crate + 1-excluded
   note; the count becomes 16 active.

### Critical files

- `crates/datasynth-graph/src/exporters/` — new writers ported from
  the excluded crate.
- `attic/datasynth-graph-export/` — new location.
- `Cargo.toml` — remove from `exclude` list.
- `CLAUDE.md` — architecture section update.

### Testing

- Existing graph-export regression tests continue to pass
  byte-identically (no behavior change on the embedded path).
- New exporter smoke tests for ported features.

### Rollback

- Git revert restores the excluded crate; attic move is trivially
  reversible.
