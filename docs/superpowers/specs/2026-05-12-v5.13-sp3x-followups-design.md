# v5.13 — SP3.x Follow-ups Design Spec

**Date:** 2026-05-12
**Status:** Draft (post-brainstorming, autonomous-execution-approved)
**Sub-projects bundled:** SP3.1, SP3.2, SP3.3, SP3.4 (consolidated v5.13 release)
**Predecessor:** [v5.12 baseline](../../baselines/2026-05-12-sp3-v5.12.0/SUMMARY.md) — composite BF 37.0×, with three regressions and one originally-deferred item

## 1. Overview

The v5.12 release dropped DataSynth's composite behavioral-fidelity score from 59.0× to 37.0×. That run also surfaced three regressions and reminded us of one item originally deferred from SP3 main. v5.13 closes all four with bounded, opt-in patches.

| Sub-project | Closes | Approach |
| --- | --- | --- |
| SP3.1 | P1 autocorrelation regressed 0.90× → 5.32× | Replace linear-mixing coupling in `ConditionalIETSampler` with Gaussian-copula coupling |
| SP3.2 | P2 BurstLen @ 7d regressed 18.17× → 57.00× | Replace single-window `SourceActiveWindow` with `MultiSegmentActiveWindow` driven by a new `ActiveSegmentsPrior` |
| SP3.3 | P3 Clustering 36.65× / TriangleLogRatio 46.09× unchanged | Add `CrossEntityMotifSampler` that biases `BipartiteFanoutSampler` toward shared-attribute pools per entity cluster |
| SP3.4 | P4 mean velocity gap 4.13× (originally deferred from SP3 §1.3) | Online `VelocityCalibrator`: periodic rule-trigger sampling + bounded parameter nudges |

All four ship in a single v5.13 release. Each is independently disable-able via the opt-in flag tree — defaulting to off for SP3.4, on (replacing the v5.12 behavior) for SP3.1-3 once priors are enabled.

### 1.1 Target outcome

Re-running the SP1 scorer against the held-out corpus with the v5.13 priors-enabled config should produce:

- **Composite BF: 12-18× target** (down from 37.0× at v5.12)
- **P1 autocorrelation: ≤1.5×** (back near the noise floor)
- **P2 BurstLen @ 7d: ≤15×**
- **P3 Clustering: ≤15×**, **TriangleLogRatio: ≤20×**
- **P4 mean gap: ≤2×**

If the actual numbers come in materially better or worse, the regression triage is the same: file the specific sub-metric as an SP3.x.y patch.

### 1.2 Goals

- SP3.1: Replace `ConditionalIETSampler::sample_next`'s linear-mixing autocorr coupling with a Gaussian-copula coupling. Skip coupling when |ρ| < 0.1 (no-coupling source — saves cycles).
- SP3.2: Add `ActiveSegmentsPrior` to `BehavioralPriors`. Add `MultiSegmentActiveWindow` sampler. Update extractor + aggregator + loader. Regenerate the five committed bundles.
- SP3.3: Add `EntityClustersPrior` and `CrossEntityMotifSampler`. Hook into `BipartiteFanoutSampler::pick_for` via an optional neighbor-hint parameter.
- SP3.4: Add `VelocityCalibrator` (online). Triggers off a new `industry_profile.priors.velocity_calibration: bool` sub-flag (default false). Adjusts five generator parameters: round-dollar bias (R9), backdating share (R10), off-hours bias (R7), post-close share (R8), amount-spike threshold (R6).
- Re-baseline against the held-out corpus and commit `docs/baselines/2026-05-XX-v5.13.0/` (date filled in at run time).
- Update `docs/entity-aware-generation.md`, CHANGELOG, README, CLAUDE.md, and the bundled config schema to reflect the new sub-flags.
- All existing tests stay green. Priors-disabled path remains v5.11.

### 1.3 Non-goals

- **CoA taxonomy mining (SP2b).** Real CoAs carry hierarchical semantics worth mining; that's a separate spec ("v5.14 SP2b") with its own corpus extraction + generator changes.
- **Cross-domain priors.** Banking (KYC/AML), OCEL event logs, payroll, manufacturing. Out of scope for the behavioral-fidelity initiative as currently framed.
- **Differential privacy on bundle consumption.** Bundles are already client-aggregated; DP at consumption is a separate concern.
- **Multi-region per-Source patterns.** SP3.2's multi-segment is per-Source, not per-(Source, region). Adequate for the evaluated corpus industry profile.
- **Cross-Source coupling at the IET level.** SP3.1 fixes within-Source autocorrelation. Across-Source dependencies (e.g., RV always follows DZ) would be a separate `JointSourceIetSampler`.

## 2. Architecture per sub-project

### 2.1 SP3.1 — Gaussian-copula autocorr coupling

**File:** `crates/datasynth-core/src/distributions/conditional_iet.rs`

Replace the existing `sample_next` body. The current code does:

```rust
let coupled = rho * prev + (1.0 - rho.abs()) * raw_sample;
```

This produces samples whose *empirical* lag-1 correlation exceeds the configured ρ because the mixing weights don't account for the marginal distribution. With heavy-tailed IETs, large `prev` values dominate the next sample regardless of ρ.

The fix uses a Gaussian copula:

```rust
fn sample_next<R: Rng>(&mut self, source: &str, rng: &mut R) -> f64 {
    let state = self.per_source.get_mut(source).unwrap_or(&mut self.fallback);
    if state.cdf_values.is_empty() {
        return 0.0;
    }
    let rho = state.lag1_autocorr.clamp(-1.0, 1.0);

    // Skip coupling for low-|ρ| sources — independent draw.
    if rho.abs() < 0.1 || state.last_iet_days.is_none() {
        let s = state.sample_quantile(rng).max(0.0);
        state.last_iet_days = Some(s);
        return s;
    }

    // Gaussian-copula coupling:
    // 1. Map prev IET to its CDF quantile p_prev.
    // 2. Convert to Gaussian z_prev = Φ⁻¹(p_prev).
    // 3. Sample z_curr | z_prev ~ N(ρ z_prev, 1-ρ²).
    // 4. Convert back to quantile p_curr = Φ(z_curr).
    // 5. Inverse-CDF sample at p_curr from the prior.
    let prev = state.last_iet_days.unwrap();
    let p_prev = empirical_cdf_at(&state.cdf_values, &state.cdf_probabilities, prev);
    let z_prev = inverse_standard_normal(p_prev.clamp(1e-6, 1.0 - 1e-6));
    let z_curr = rho * z_prev + (1.0 - rho * rho).sqrt() * standard_normal_sample(rng);
    let p_curr = standard_normal_cdf(z_curr).clamp(0.0, 1.0);
    let curr = quantile_at(&state.cdf_values, &state.cdf_probabilities, p_curr).max(0.0);

    state.last_iet_days = Some(curr);
    curr
}
```

Helpers `empirical_cdf_at`, `quantile_at`, `inverse_standard_normal`, `standard_normal_cdf`, `standard_normal_sample` live in the same file. `inverse_standard_normal` uses the rational approximation from Acklam (or equivalent — `statrs::distribution::Normal::inverse_cdf` is the simplest path if it's already available in the workspace).

**Why this works:** With ρ=0.5, the conditional distribution `z_curr | z_prev` has mean `0.5*z_prev` and variance `0.75`. After inverse-CDF, the empirical lag-1 correlation of the coupled samples matches ρ — that's the Gaussian-copula property. The existing linear mixing didn't have that guarantee.

**Test:** Sample 10K coupled IETs from a known prior with ρ=0.5. Compute the empirical lag-1 correlation of the resulting series. Assert it's within ±0.05 of 0.5.

**Extractor:**

```rust
pub const SEGMENT_GAP_THRESHOLD_DAYS: i64 = 7;

pub fn extract_active_segments(records: &[Record]) -> ActiveSegmentsPrior {
    let mut by_source: BTreeMap<String, Vec<NaiveDate>> = BTreeMap::new();
    for r in records {
        by_source.entry(r.source.clone()).or_default().push(r.entry_date);
    }
    let mut summaries = BTreeMap::new();
    for (src, mut dates) in by_source {
        dates.sort();
        dates.dedup();
        if dates.len() < 2 {
            continue;
        }
        // Walk dates, split into segments on gap > SEGMENT_GAP_THRESHOLD_DAYS.
        let (segments, gaps) = split_into_segments(&dates, SEGMENT_GAP_THRESHOLD_DAYS);
        let segment_count = segments.len() as u32;
        let segment_lengths: Vec<u32> = segments
            .iter()
            .map(|s| ((s.1 - s.0).num_days().max(0)) as u32)
            .collect();
        let summary = SourceSegmentSummary {
            segment_count_histogram: LineCountHistogram::build(&[segment_count], &SEGMENT_COUNT_BUCKETS).0,
            segment_length_histogram: LineCountHistogram::build(&segment_lengths, ACTIVE_LIFETIME_DAY_BUCKETS).0,
            gap_length_histogram: LineCountHistogram::build(&gaps, &SEGMENT_GAP_BUCKETS).0,
        };
        summaries.insert(src, summary);
    }
    ActiveSegmentsPrior { by_source: summaries }
}
```

// In source_active_window.rs:

#[derive(Debug, Clone)]
pub struct MultiSegmentActiveWindow {
    pub by_source: HashMap<String, Vec<ActiveWindow>>,
    pub period_days: i64,
}

impl MultiSegmentActiveWindow {
    pub fn build<R: Rng>(
        sources: &[String],
        period_days: i64,
        prior: &ActiveSegmentsPrior,
        fallback_lifetime_sampler: impl FnMut(&mut R) -> i64,
        rng: &mut R,
    ) -> Self {
        let mut by_source: HashMap<String, Vec<ActiveWindow>> = HashMap::new();
        for src in sources {
            let segments = if let Some(summary) = prior.by_source.get(src) {
                place_segments_from_prior(summary, period_days, rng)
            } else {
                let life = fallback_lifetime_sampler(rng).min(period_days).max(0);
                let start = if period_days - life <= 0 { 0 } else { rng.random_range(0..=(period_days - life)) };
                vec![ActiveWindow { start_day: start, end_day: start + life }]
            };
            by_source.insert(src.clone(), segments);
        }
        Self { by_source, period_days }
    }

    pub fn is_active(&self, source: &str, day: i64) -> bool {
        match self.by_source.get(source) {
            Some(segments) => segments.iter().any(|w| w.contains(day)),
            None => day >= 0 && day < self.period_days,
        }
    }
}
```

`place_segments_from_prior` samples (segment_count, lengths, gaps) and lays them out across `[0, period_days]` with random placement of the first segment.

**Aggregator:** mirrors the existing `aggregate_active_lifetime` — pools the histograms per Source across clients.

**Loader change:** `LoadedPriors` gets a new field `pub multi_segment_window: Option<MultiSegmentActiveWindow>`. When the bundle's `active_segments` is `Some`, use it; otherwise fall back to the existing `active_window`. je_generator's `is_active` check uses the multi-segment one when present.

#[derive(Debug, Clone, PartialEq, Default, Serialize, Deserialize)]
pub struct EntityClustersPrior {
    /// Entity clusters discovered in the corpus bipartite graph.
    /// Each cluster is a set of Sources that share attribute pools heavily.
    pub clusters: Vec<EntityCluster>,
    /// Probability that a Source is in *some* cluster (vs. an isolate).
    pub clustering_rate: f64,
}

#[derive(Debug, Clone, PartialEq, Default, Serialize, Deserialize)]
pub struct EntityCluster {
    /// Source codes in this cluster.
    pub members: Vec<String>,
    /// Average pairwise Jaccard similarity on attribute sets (0..1).
    pub avg_jaccard: f64,
}
```

**Extraction approach:** For each `(Source, attribute)` pair, build the attribute set per Source. Compute pairwise Jaccard similarity. Greedy cluster: pairs with Jaccard > 0.3 form edges; connected components become clusters. Singletons drop.

```rust
pub fn extract_entity_clusters(records: &[Record]) -> EntityClustersPrior {
    let mut attr_sets: BTreeMap<String, HashSet<String>> = BTreeMap::new();
    for r in records {
        let key = r.source.clone();
        attr_sets.entry(key).or_default().insert(r.gl_account.clone());
        if let Some(cc) = &r.cost_center {
            attr_sets.entry(r.source.clone()).or_default().insert(format!("CC:{cc}"));
        }
        // … similar for ProfitCenter, TradingPartner …
    }
    // Compute pairwise Jaccard, threshold at 0.3, connected components.
    let sources: Vec<String> = attr_sets.keys().cloned().collect();
    let mut adj: BTreeMap<String, Vec<String>> = BTreeMap::new();
    let mut edge_weights: Vec<(String, String, f64)> = Vec::new();
    for i in 0..sources.len() {
        for j in (i + 1)..sources.len() {
            let a = &attr_sets[&sources[i]];
            let b = &attr_sets[&sources[j]];
            let intersection = a.intersection(b).count() as f64;
            let union = a.union(b).count() as f64;
            if union == 0.0 { continue; }
            let jaccard = intersection / union;
            if jaccard > 0.3 {
                adj.entry(sources[i].clone()).or_default().push(sources[j].clone());
                adj.entry(sources[j].clone()).or_default().push(sources[i].clone());
                edge_weights.push((sources[i].clone(), sources[j].clone(), jaccard));
            }
        }
    }
    // Connected components → clusters.
    let mut visited: HashSet<String> = HashSet::new();
    let mut clusters: Vec<EntityCluster> = Vec::new();
    for src in &sources {
        if visited.contains(src) { continue; }
        let mut members = Vec::new();
        let mut stack = vec![src.clone()];
        while let Some(s) = stack.pop() {
            if !visited.insert(s.clone()) { continue; }
            members.push(s.clone());
            if let Some(neighbors) = adj.get(&s) {
                for n in neighbors {
                    if !visited.contains(n) {
                        stack.push(n.clone());
                    }
                }
            }
        }
        if members.len() >= 2 {
            // Compute avg Jaccard within the cluster.
            let mut sum = 0.0;
            let mut count = 0.0;
            for i in 0..members.len() {
                for j in (i + 1)..members.len() {
                    for (a, b, w) in &edge_weights {
                        if (a == &members[i] && b == &members[j]) || (a == &members[j] && b == &members[i]) {
                            sum += w;
                            count += 1.0;
                            break;
                        }
                    }
                }
            }
            let avg_jaccard = if count > 0.0 { sum / count } else { 0.0 };
            clusters.push(EntityCluster { members, avg_jaccard });
        }
    }
    let clustering_rate = clusters.iter().map(|c| c.members.len()).sum::<usize>() as f64
        / sources.len().max(1) as f64;
    EntityClustersPrior { clusters, clustering_rate }
}
```

**Sampler:** A small lookup that, given an entity, returns its cluster's other members.

```rust
// In cross_entity_motifs.rs:

#[derive(Debug, Clone)]
pub struct CrossEntityMotifSampler {
    pub neighbors_of: HashMap<String, Vec<String>>,
    pub clustering_rate: f64,
}

impl CrossEntityMotifSampler {
    pub fn from_prior(prior: &EntityClustersPrior) -> Self {
        let mut neighbors_of: HashMap<String, Vec<String>> = HashMap::new();
        for cluster in &prior.clusters {
            for member in &cluster.members {
                let others: Vec<String> = cluster
                    .members
                    .iter()
                    .filter(|m| m != &member)
                    .cloned()
                    .collect();
                neighbors_of.insert(member.clone(), others);
            }
        }
        Self { neighbors_of, clustering_rate: prior.clustering_rate }
    }

    /// Returns the cluster-mates of `entity` (or empty if isolate).
    pub fn neighbors(&self, entity: &str) -> &[String] {
        self.neighbors_of.get(entity).map(|v| v.as_slice()).unwrap_or(&[])
    }

    /// Probability that we should pick a "shared" value vs a fresh one for `entity`.
    pub fn should_share(&self, entity: &str) -> f64 {
        if self.neighbors_of.contains_key(entity) {
            self.clustering_rate
        } else {
            0.0
        }
    }
}
```

**Hook into BipartiteFanoutSampler:** Add a new method that takes an optional neighbor list:

```rust
// In fanout_sampler.rs:

impl BipartiteFanoutSampler {
    /// SP3.3: pick an attribute value preferring buckets already used by a neighbor.
    /// Falls back to the existing pick_for when no neighbors have used any bucket.
    pub fn pick_for_with_neighbors<R: Rng>(
        &mut self,
        entity_id: &str,
        neighbors: &[String],
        share_probability: f64,
        rng: &mut R,
    ) -> String {
        if self.buckets.is_empty() {
            return String::new();
        }
        // With probability `share_probability`, try to pick a bucket already used by a neighbor.
        if !neighbors.is_empty() && rng.random_range(0.0..1.0) < share_probability {
            let neighbor_buckets: Vec<usize> = (0..self.buckets.len())
                .filter(|&i| {
                    neighbors
                        .iter()
                        .any(|n| self.buckets[i].current_users.contains(n))
                })
                .collect();
            if !neighbor_buckets.is_empty() {
                let chosen_idx = neighbor_buckets[rng.random_range(0..neighbor_buckets.len())];
                self.buckets[chosen_idx]
                    .current_users
                    .insert(entity_id.to_string());
                return self.buckets[chosen_idx].attribute_value.clone();
            }
        }
        // Fall back to the existing capacity-based pick.
        self.pick_for(entity_id, rng)
    }
}
```

### 2.4 SP3.4 — Velocity-rule calibrator

**Files:**
- `crates/datasynth-generators/src/velocity_calibrator.rs` — new module
- `crates/datasynth-config/src/schema.rs` — add `velocity_calibration: bool` to `IndustryPriorsConfig`
- `crates/datasynth-generators/src/je_generator.rs` — invoke calibrator periodically when enabled

**Approach:** every N=10,000 emitted lines, snapshot the current rule-trigger rates and compare against the prior's target. For each off-target rule, nudge the affected generator parameter by a small bounded step. The five tunable parameters:

| Rule | Adjustable parameter | Step | Bound |
| --- | --- | --- | --- |
| R6 amount-spike | `amounts.lognormal_sigma` | ±0.01 | [1.0, 4.0] |
| R7 off-hours | `fraud.off_hours_bias` (or new `posting.off_hours_share`) | ±0.005 | [0.0, 0.5] |
| R8 post-close | `period_close.post_close_share` | ±0.005 | [0.0, 0.3] |
| R9 round-dollar | `fraud.round_dollar_bias` (or new `amounts.round_dollar_share`) | ±0.005 | [0.0, 0.5] |
| R10 backdating | new `posting.backdating_share` | ±0.005 | [0.0, 0.3] |

**Calibrator skeleton:**

The calibrator only computes target rates from priors at init (cheap). Per-line observation just counts trigger events for the current window. Every N lines, it computes per-rule observed rate, picks the most-off rule, applies one bounded step, and resets the window.

The actual parameter mutation happens on the je_generator state; the calibrator returns a `CalibrationStep` and the generator applies it. This keeps the calibrator pure (testable in isolation) and the generator-mutation explicit.

**Config gate:** `industry_profile.priors.velocity_calibration: false` (default). When `true`, the calibrator is built and invoked. When `false`, no observation overhead.

## 3. Data flow summary

```
LoadedPriors:
  ConditionalIETSampler (SP3.1 — copula coupling)
  MultiSegmentActiveWindow (SP3.2 — replaces SourceActiveWindow when present)
  BipartiteFanoutSampler[s] (existing, called via pick_for_with_neighbors)
  CrossEntityMotifSampler (SP3.3 — new, optional)
  VelocityCalibrator (SP3.4 — new, built only when velocity_calibration=true)

je_generator emission loop:
  active_window.is_active(source, day) → uses multi-segment when present
  iet_sampler.sample_next(source) → uses Gaussian copula
  fanout_sampler.pick_for_with_neighbors(source, motif_neighbors, share_prob)
  emit line(s)
  velocity_calibrator.observe_line(line) → may return a CalibrationStep
  generator applies the CalibrationStep to its tunable parameters
```

## 5. Dependencies + risks

### 5.1 Dependencies

No new heavy dependencies. `statrs::distribution::Normal` for `inverse_cdf` (already a workspace dep). All other math is in-place.

### 5.2 Risks

- **SP3.1**: if `statrs::Normal::inverse_cdf` performs poorly for extreme p values (e.g., p < 1e-6), the clamp at `[1e-6, 1 - 1e-6]` handles it. Validated by the new unit test.
- **SP3.2**: corpus extraction will now do per-Source segment detection across multi-million-row files. Mitigation: streamed segment splitting (no full sort of all dates; sort per-Source once which is what the existing extractor already does).
- **SP3.3**: pairwise Jaccard over ~30-100 Sources is O(N²) which is fine. Across the 1279 sources in the aggregated health bundle though, it would be O(N²) = 1.6M comparisons. Mitigation: bound `extract_entity_clusters` to top-K Sources by row count (K=50 default) — clusters of rare Sources have low signal anyway.
- **SP3.4**: parameter nudging could oscillate if step sizes are too large or target rates are unreachable. Mitigation: bounded steps, hysteresis (don't change direction more than once per 5 windows), hard bounds per parameter.
- **Bundle size growth**: adding two new priors to each industry bundle. Estimated +10-30 KB per bundle (multi-segment histograms + cluster lists). Acceptable — committed bundles stay under 2 MB.
- **Existing test stability**: the priors-disabled path is unchanged; SP3.1/3.2/3.3 only activate when priors loaded. Backward-compat tests verify.
